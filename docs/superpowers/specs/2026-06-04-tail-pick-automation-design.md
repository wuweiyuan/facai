# Tail Pick Automation Design

## Goal

Automate the isolated `tail-pick` command on macOS at 14:44 on weekdays, while keeping output separate from existing recommendation reports and leaving the original strategy flow unchanged.

## Design

Add a project-local runner script that executes `python3 -m app.main tail-pick` from the repository root and writes logs under `reports/tail_pick/`. Add install and uninstall scripts for a user-level `launchd` plist. The plist runs Monday through Friday at 14:44 Asia/Shanghai/local machine time.

The launchd plist will be generated by a small Python helper so the schedule, working directory, and log paths can be tested. The install script writes the plist to `~/Library/LaunchAgents/com.wayne.tail-pick.plist` and loads it with `launchctl`. The uninstall script unloads and removes the same file.

## Boundaries

- Do not write to existing recommendation CSV/Markdown/TXT files.
- Do not place orders.
- Do not install system-level daemons.
- Do not run on weekends.
- Weekday-only launchd does not understand Chinese market holidays; holiday runs will simply log no usable result or data-source failure.
